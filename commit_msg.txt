fix(#896): write keypairs to GITHUB_OUTPUT so Friendbot stops rejecting the nightly

Root cause: both keypair steps escaped \$GITHUB_OUTPUT, so the value
landed in a file literally named '$GITHUB_OUTPUT' and the real output
file stayed empty. steps.keygen.outputs.public was therefore empty,
the Friendbot URL became '?addr=', Friendbot answered 400 and curl
exited 22 — a configuration bug, not a testnet outage.

- write to "$GITHUB_OUTPUT" (unescaped) in both keygen steps
- assert both public keys are non-empty before use, with a readable error
- retry Friendbot on 429/5xx/timeout (3 attempts, 5/10s backoff),
  print body and HTTP status on a real rejection
